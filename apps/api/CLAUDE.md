Читай спочатку `docs/plan/02-backend.md` і `docs/plan/07-contracts.md`.
- Маршрути — у `src/routes/*`, по файлу на ресурс; схеми запитів і відповідей імпортуються з `@khronist/contracts`, не оголошуються локально.
- Будь-яка робота з БД — через Drizzle і `src/db/schema.ts`; нова таблиця = міграція `drizzle-kit generate` у тому ж PR.
- Довгі операції (читання, нормалізація) — тільки у фонових задачах `src/jobs`; виняток — `POST /v1/explain` і `/v1/chat`, які за контрактом відповідають синхронно. Маршрут читання повертає 201 і `recognitionId`; стан задачі — у таблиці `recognitions`, не в пам'яті.
- Читання рукопису — лише через `src/services/htr`; реалізацію обирає `selectHtrReader`; `HTR_URL` (трек B) ще не реалізовано. LLM — лише через `src/services/llm`; промпти беруться з `@khronist/prompts`, тексти промптів у коді не пишуться.
- Будь-яка відповідь із пояснення або чату без валідних `citations` — це `answer: null`. Цю перевірку робить код, не промпт.
- Пошук по корпусу — повнотекст + `pg_trgm` + `synonyms`; ембедингів не додавати.
- Тести: юніт для `calendar`, `citation`, парсерів, перевірки citations; інтеграційні для маршрутів проти PGlite з фальшивими ридерами й провайдерами (`test/helpers.ts`); зв'язку зі справжнім PostgreSQL перевіряє `pnpm --filter @khronist/api smoke` у CI.
