# apps/extension

Розширення Chrome (Manifest V3) на WXT 0.21 і React 19. Стилі й компоненти — з `@khronist/ui`.

## Запуск

- `pnpm --filter @khronist/extension dev` — WXT відкриває окремий Chrome із розширенням і перезбирає його при змінах.
- `pnpm --filter @khronist/extension build` — збірка в `.output/chrome-mv3`. Встановити: `chrome://extensions` → «Режим розробника» → «Завантажити розпаковане» → тека `.output/chrome-mv3`.
- `pnpm --filter @khronist/extension zip` — архів для GitHub Release.

`pnpm install` запускає `wxt prepare`, який генерує `.wxt/` з типами; без нього `tsconfig.json` не знайде базову конфігурацію.

## Що є

- `entrypoints/background.ts`: панель відкривається кліком по іконці (`sidePanel.setPanelBehavior`) і гарячою клавішею `Alt+Shift+X` (команда `open-panel` викликає `sidePanel.open`, як радить документація Chrome: відкриття лише у відповідь на дію користувача).
- `entrypoints/archium.content.tsx`: content script на е-ресурсах ARCHIUM (поки лише `archium.cdiak.archives.gov.ua`). На сторінці переглядача `/file-viewer/:id` читає шифр і надсилає його панелі; перераховує при зміні адреси (`wxt:locationchange`, зокрема хеш `#file-…`) і коли застосунок дорендерює сторінку. За командою панелі показує накладку виділення (`SelectionOverlay` з `@khronist/ui`) у shadow root (`createShadowRootUi`, `cssInjectionMode: 'ui'`); стилі — лише `@khronist/ui/theme.css`, без шрифтів, щоб не чіпати сторінку порталу. `zIndex` з опцій WXT не працює: скидання `:host { all: initial !important }` усередині shadow root перебиває inline-стилі хоста, і накладка опинялася під переглядачем ARCHIUM. Тому `position` і `z-index` хоста задано в `css` того ж shadow root з `!important`. Esc або «Скасувати» в панелі прибирають накладку. Після оновлення розширення старий content script лишається на відкритих вкладках без `browser.runtime`; перед кожним надсиланням перевіряється `ctx.isInvalid`, і такий скрипт вимикається сам. Щоб розширення знову працювало на вкладці, її треба перезавантажити.
- `scan/fragment.ts`: виділення на екрані переводиться в пікселі оригіналу через `getBoundingClientRect()` і `naturalWidth`/`naturalHeight` скану (переглядач показує його зменшеним), обрізається межами скану й вирізається через `OffscreenCanvas` у PNG без масштабування. Поруч рахуються SHA-256 від байтів PNG (як у `POST /v1/recognitions`) і рамка в частках розміру зображення. Результат іде повідомленням `fragment`; панель використає його в наступному кроці (читання).
- `portal/archium.ts`: скан (`findArchiumScan` → `img#main-image`) і читання шифру. Фонд, опис і справа беруться з посилань `/fonds/`, `/inventories/`, `/files/` у блоці `.description-item` (не з підписів, бо в ARCHIUM є англійська версія). Номер зображення — `data-page` того елемента стрічки `#all-images`, чий `src` збігається з `img#main-image`, тобто того скану, що на екрані. Архів визначає хост: `archium.cdiak.archives.gov.ua` → «ЦДІАК України». Розмітку описано в `docs/portal-searcharchives.md`, розділ 6.
- `entrypoints/sidepanel/`: React-застосунок панелі. `useActivePage` питає content script активної вкладки (`tabs.sendMessage`), слухає його повідомлення й оновлюється при перемиканні вкладок. Повідомлення перевіряються схемами з `messages.ts`. Коли скан відкрито, панель показує стан B2 «Виділіть фрагмент скану» з кнопкою «Виділити фрагмент», під час виділення — B3 «Обведіть запис на аркуші» з кнопкою «Скасувати». Повторне `Alt+Shift+X` при відкритій панелі вмикає виділення: команду слухає сама панель, тому перше натискання лише відкриває її.
- `api/`: клієнт API. Адреса — `api/origin.ts` (`https://api.khronist.org`), з неї ж береться `host_permissions` у маніфесті: запити з панелі до хоста з дозволу Chrome не перевіряє через CORS, тож `CORS_ORIGINS` на сервері для розширення не потрібен і ID розширення не має значення. `readRecognition` надсилає фрагмент у `POST /v1/recognitions`, читає стан `GET /v1/recognitions/:id` і, доки читання не завершилось, слухає `GET /v1/recognitions/:id/events` через `fetch` зі стрімінгом (`api/events.ts` розбирає SSE). Якщо потік закрився без `done` чи `failed` (сервер закриває його через 5 хвилин), стан перепитується й підписка відновлюється. Помилки API приходять як `ApiFailure` із повідомленням сервера.
- `entrypoints/sidepanel/useReading.ts`: стан читання в панелі. Після виділення content script надсилає фрагмент разом із шифром, панель показує B4 «Розпізнаємо» (прев'ю фрагмента, кроки «Читання рукопису» й «Нормалізація та сутності», рядки), потім B5 (рядки з підкресленими непевними словами й текст сучасною орфографією; цей блок з'являється, лише якщо сервер повернув текст, відмінний від сирих рядків — поки нормалізація на сервері заглушка, його немає) або E3 з причиною від сервера. Без мережі той самий екран показує `StatusBar` типу error. «Скасувати» лише перестає чекати: сервер дочитає фрагмент, і повторне виділення того самого місця прийде з кешу.
- Дозволи: `sidePanel` і `host_permissions` для API; доступ до сторінок ARCHIUM дає `content_scripts.matches`. Нові дозволи додаються разом із функцією, якій вони потрібні.

Тести (`pnpm --filter @khronist/extension test`, jsdom) читають шифр із `test/fixtures/archium-viewer.html` — скороченої розмітки переглядача справи ф. 127, оп. 1078, спр. 177 — і перевіряють перерахунок виділення в пікселі скану, рамку, SHA-256 і base64, розбір SSE (події, розбиті між шматками, CRLF, `: ping`), цикл читання на підміненому `fetch` (кеш, потік до `done`, помилка API) і переходи стану панелі. Саме вирізання (`OffscreenCanvas`) jsdom не має; його перевірено в Chrome на скані `/static/files/283/2834611.jpg`.

Автоімпорти WXT вимкнено (`imports: false`): усе імпортується явно з `wxt/browser`, `wxt/utils/*` і пакетів.

Користувач може змінити гарячу клавішу на `chrome://extensions/shortcuts`; якщо `Alt+Shift+X` зайнята іншим розширенням, Chrome її не призначить. Запропоновану клавішу Chrome призначає лише під час встановлення: якщо розширення встановлено до появи команди й потім оновлено кнопкою «Оновити», клавіші не буде. Тоді задати її вручну на `chrome://extensions/shortcuts` або видалити розширення й завантажити розпаковане знову.
