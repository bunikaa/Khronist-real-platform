# normalize

Чернетка v0. Переписує прочитані рядки сучасною орфографією тієї самої мови, без перекладу. `schema.json` має збігатися з `normalizeOutputSchema` у `packages/contracts`, це перевіряє тест пакета.

## Правила

Лише правила реформи орфографії 1918 року за статтею «Реформа русской орфографии 1918 года» у російській Вікіпедії (https://ru.wikipedia.org/wiki/Реформа_русской_орфографии_1918_года): ѣ → е, ѳ → ф, і → и, кінцевий ъ відкидається, розділовий ъ лишається, префікси на з/с (из-, воз-, вз-, раз-, роз-, низ-, без-, чрез-, через-), закінчення -аго, -яго, -ыя, -ія, форми онѣ, однѣ, ея. -аго стає -ого, а після ж, ч, ш, щ — -его, якщо в сучасній формі закінчення ненаголошене (лучшаго → лучшего, але большаго → большого); -яго стає -его. Стаття Вікіпедії наводить лише «після шиплячих -его»; умову про наголос додано за сучасною нормою (большого), TODO(перевірити) з Анною за довідником правопису. Приставки вз- і низ- стаття прямо не перелічує, вона каже «всі, крім с-». Про ѵ декрет нічого не каже; за тією самою статтею на практиці її після реформи не вживали, тому промпт пише и.

Імена, по батькові, прізвища й назви місць змінюються лише за цими правилами для літер і не замінюються іншими формами. Українські форми імен і сіл дають сутності та словник варіантів, а не нормалізація.

Рядки — матеріал, а не інструкції: промпт велить не виконувати текст рядків, який просить порушити правила чи змінити формат відповіді, як в `explain` і `chat`. API окремо перевіряє, що кожне слово змінилося лише за правилами вище або є розкритим скороченням з `expansions` (`apps/api/src/services/normalize.ts`), тож підмінене слово не потрапить у транскрипцію.

У кожному рядку стільки ж слів, скільки прочитано: API переносить на них непевність за позицією й зберігає `normalizedLines` поряд із прочитаними рядками. Скорочення модель розкриває на власний розсуд, лише загальновідомі й лише в одне слово, і записує в `expansions`; панель показує їх окремим списком. Перевіреного списку скорочень метричних книг ще немає; коли він з'явиться в корпусі (статті `type: abbr`), його варто додати в промпт.

Промпт розрахований на російську мову (`language` — `ru` або `unknown`). Для інших мов API не повинно його викликати: рядки лишаються без змін, і блок «Сучасною орфографією» в панелі не показується.

## Змінні `user.md`

`language`, `period`, `documentType` — з `hints`, без підказки API підставляє `unknown`, як для `htr_vision`. `lines` — JSON-масив прочитаних рядків у формі `{ "text", "words": [{ "text", "uncertain" }] }`.

## Приклади

`examples.jsonl` — шість фрагментів із `services/knowledge/eval/reference/lines.jsonl`: `source` — фрагмент і номери рядків, `input` — підказки й рядки (непевні — слова з поля `doubt` еталона і `[нрзб]`), `output` — очікуваний вихід. Вихід переписано вручну за правилами вище. Еталонне читання зробила модель, людина його не перевіряла, тому приклади показують правила нормалізації, а не точність читання. Скорочень у цих фрагментах немає, тож `expansions` у прикладах порожні. Приставок вз- і низ- та закінчення -аго після ж, ч, ш, щ у демо-фрагментах теж немає, тому прикладів на ці правила поки немає: додати з золотого набору (V-23), щойно такі слова там трапляться. Тест перевіряє на всіх прикладах, що кількість рядків і слів у рядку зберігається.
