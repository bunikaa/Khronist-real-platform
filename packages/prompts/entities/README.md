# entities

Чернетка v0. Знаходить людей, місця, терміни й дати в нормалізованому тексті фрагмента. Контракт — `docs/plan/07-contracts.md`, розділ 9; `schema.json` має збігатися з `entitiesOutputSchema` у `packages/contracts`, це перевіряє тест пакета.

## Правила

- `person` — одна сутність на людину: ім'я, по батькові й прізвище, як вони стоять поруч у тексті. Духовенство, восприємники й свідки — теж `person`. Стан чи чин перед ім'ям до людини не входить.
- `place` — село, місто, парафія, повіт чи губернія.
- `term` — те, що сучасному читачеві треба пояснити: стани (крестьянин, собственник, мещанин), церковні чини (священник, псаломщик, диакон), таїнства й ролі в них (восприемники), віросповідання, одиниці й гроші. Звичайні слова (жена, сын, его) — не терміни. Для `term` панель показуватиме «Пояснити».
- `date` — дата чи рік як написано; обчислює їх код (`calendar.ts`), не модель.
- `normalized` — початкова форма в сучасній орфографії тієї самої мови, без перекладу й без українських форм: їх дають словник варіантів і корпус. Перенесене слово з'єднується без дефіса.
- `[нрзб]` до сутності не входить; людина без читабельного імені пропускається.

Позицій у виході немає: `start`/`end` рахує API, шукаючи кожен `text` у `normalizedText` після попереднього знайденого, тому сутності йдуть у порядку появи, кожне входження окремо.

## Змінні `user.md`

`language`, `period`, `documentType` — з `hints`, без підказки API підставляє `unknown`. `text` — `normalizedText` транскрипції, рядки через `\n`.

## Приклади

`examples.jsonl` — шість фрагментів з `services/knowledge/eval/reference/lines.jsonl` у нормалізованому вигляді: чотири — вихід прикладів `normalize`, два (`2276_6_parents:0-4`, `177_4_parents:6-10`) нормалізовано вручну за тими самими правилами. Сутності розмічено вручну. Еталонне читання зробила модель, людина його не перевіряла.
