## Вступ

### Базові адреси

| Середовище | Адреса                    |
| ---------- | ------------------------- |
| Прод       | `https://api.khronist.org` |
| Локально   | `http://localhost:3000`   |

Локальний порт задає змінна `PORT` (за замовчуванням `3000`).

### Формат і версіювання

- Тіла запитів і відповідей — JSON у UTF-8 (`content-type: application/json`). Виняток — потік подій `GET /v1/recognitions/:id/events` (`text/event-stream`).
- Маршрути ресурсів мають префікс `/v1`. Маршрути входу живуть окремо, під `/api/auth/` (без `/v1`), бо їх обслуговує бібліотека автентифікації.
- Ідентифікатори — UUID. Дати й час — рядки ISO 8601 (`2026-11-18T09:30:00.000Z`).
- Координати рамок (`box`) — частки від розміру зображення, `0..1`.
- Кожна відповідь має заголовок `x-request-id`. Якщо клієнт надіслав `x-railway-request-id`, сервер повертає це значення, інакше генерує UUID. Вказуйте його, коли повідомляєте про помилку.
- Невідомі маршрути відповідають `404` у форматі помилки (див. нижче).

### CORS

Дозволені джерела (origin) задає змінна `CORS_ORIGINS` на сервері; без неї кросдоменні запити з браузера відхиляються. Дозволені методи: `GET`, `HEAD`, `POST`, `PATCH`, `DELETE`; дозволені заголовки запиту: `content-type`, `authorization`; `credentials: true`. Браузер бачить заголовки відповіді `retry-after`, `x-request-id`, `x-ratelimit-limit`, `x-ratelimit-remaining`, `x-ratelimit-reset` (а на маршрутах входу ще й `set-auth-token`).

### Формат помилки

Усі помилки мають однакову форму:

```json
{
  "error": {
    "code": "not_found",
    "message": "Транскрипцію не знайдено"
  }
}
```

`code` — стабільний ідентифікатор (`^[a-z][a-z0-9_]*$`), за яким працює клієнтський код; `message` — текст українською для показу людині, його формулювання може змінюватися. Деталі внутрішніх помилок клієнту не віддаються.

Коди, спільні для всіх маршрутів:

| HTTP | `error.code`       | Коли                                                                                  |
| ---- | ------------------ | ------------------------------------------------------------------------------------- |
| 400  | `bad_request`      | Тіло, параметри шляху чи запиту не пройшли валідацію; зламаний JSON; некоректний курсор |
| 401  | `unauthorized`     | Немає або недійсний вхід, ключ API чи ключ адміністратора                              |
| 403  | `forbidden`        | Вхід є, але прав недостатньо                                                           |
| 404  | `not_found`        | Ресурсу чи маршруту немає                                                              |
| 413  | `too_large`        | Тіло запиту перевищує ліміт маршруту (див. поле «Обмеження тіла» у маршрутах)          |
| 429  | `too_many_requests`| Перевищено ліміт частоти або денну квоту                                               |
| 500  | `internal_error`   | Внутрішня помилка сервера                                                              |
| 503  | `shutting_down`    | Сервер перезапускається (див. розділ про ліміти)                                       |

Валідація (`400 bad_request`) повертає загальне повідомлення «Некоректний запит» без переліку полів; перевіряйте запит за схемами цього довідника.

Маршрути додають власні коди (`bad_image`, `reader_unavailable`, `version_conflict`, `invalid_otp` та інші); вони описані біля маршрутів.

### Наявність маршрутів залежить від налаштувань сервера

| Група маршрутів                                                       | Реєструється, лише якщо                                                               |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `/api/auth/*`, `PATCH .../lines`, `POST .../verify`                   | задано `RESEND_API_KEY`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `MAIL_FROM` (вхід за кодом з пошти) |
| `/v1/admin/*`                                                         | задано `ADMIN_API_KEY`                                                                 |
| Решта (`/health`, розпізнавання, сторінки, транскрипції, пошук, цитата, пояснення, чат) | завжди                                                                       |

Якщо групу не ввімкнено, її маршрути відповідають `404 not_found`.

## Автентифікація

API має чотири рівні доступу.

| Рівень       | Як передається                                  | Що відкриває                                                                  |
| ------------ | ----------------------------------------------- | ----------------------------------------------------------------------------- |
| Гість        | нічого                                          | усі читальні маршрути, розпізнавання (з нижчою денною квотою), пояснення, чат, цитата, пошук |
| Ключ API     | `Authorization: Bearer khr_...`                 | `POST /v1/recognitions` із вищою денною квотою й збереженням метаданих документа |
| Сесія        | `Authorization: Bearer <токен сесії>` або cookie сесії | редагування рядків, підтвердження, профіль                              |
| Ключ адміністратора | `Authorization: Bearer <ADMIN_API_KEY>`  | усі `/v1/admin/*`                                                             |

### Гість

Передавати нічого не потрібно. Лічильники лімітів гостя ведуться за адресою клієнта: сервер бере її із заголовка, назву якого задає змінна `CLIENT_IP_HEADER` (значення має бути коректною IP-адресою), а без неї — з адреси TCP-з'єднання.

### Ключ API

- Формат: рядок із префіксом `khr_`. Сервер зберігає лише його SHA-256 хеш.
- Ключ створюється командою `pnpm --filter @khronist/api api-key:create "<хто користується ключем>"`; команда друкує ключ один раз.
- Діє лише на `POST /v1/recognitions`. Токен без префікса `khr_` на цьому маршруті ігнорується (запит вважається гостьовим).
- Невідомий ключ з префіксом `khr_` відхиляється з `401 unauthorized` («Невідомий ключ API»), а не переводиться в гостя. Невдалі пошуки ключів обмежено: 10 за хвилину з однієї адреси, далі `429`.
- Ліміти розпізнавань для ключа рахуються за ключем, а не за адресою.

### Сесія

Вхід — за одноразовим кодом, що приходить на пошту (розділ [Вхід і профіль](#вхід-і-профіль)):

1. `POST /api/auth/email-otp/send-verification-otp` — надіслати код.
2. `POST /api/auth/sign-in/email-otp` — обміняти код на сесію.

Успішна відповідь кроку 2 встановлює cookie сесії й повертає підписаний токен у заголовку `set-auth-token`. Далі можна передавати токен заголовком `Authorization: Bearer <токен>` (для розширення й серверних клієнтів) або покладатися на cookie (для браузера з `credentials: 'include'`). Непідписаний токен сесії сервер не приймає.

Маршрути, що вимагають сесії: `PATCH /v1/transcriptions/:id/lines`, `POST /v1/transcriptions/:id/verify`, `POST /api/auth/update-user`. Без сесії вони відповідають `401 unauthorized`. Підтверджувати (`verify`) може лише користувач, чия пошта входить до списку `VERIFIER_EMAILS` на сервері; для решти — `403 forbidden`. Чи може поточний користувач підтверджувати, повертає `GET /api/auth/get-session` у полі `canVerify`.

Запити входу перевіряються за заголовком `Origin`: джерело має входити до `CORS_ORIGINS` або бути розширенням Chrome (`chrome-extension://...`), інакше `403 invalid_origin`.

### Ключ адміністратора

Значення змінної `ADMIN_API_KEY` передається як `Authorization: Bearer <ключ>`. У production ключ має бути не коротшим за 32 символи. Порівняння виконується за сталий час; помилка — `401 unauthorized` («Потрібен ключ адміністратора»). Ключ адміністратора й ключ API — різні речі, не плутайте їх.

## Ліміти й коди 429/503

### 429 too_many_requests

Усі `429` мають формат помилки з `code: "too_many_requests"` і заголовок `retry-after` (секунди). Якщо сервер не знає точного часу очікування, він ставить `retry-after: 60`. Маршрути з лімітом частоти за замовчуванням додають заголовки `x-ratelimit-*` (поведінка бібліотеки `@fastify/rate-limit`). Клієнт має чекати вказаний час, а не повторювати запит одразу.

| Маршрут                                           | Ліміт                                                                                                  |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `POST /v1/recognitions`                           | 10 запитів на хвилину на клієнта; 3 незавершені розпізнавання на клієнта; загальна черга до 50; денна квота: гість 300, ключ API 1000 (значення за замовчуванням, змінні `GUEST_RECOGNITIONS_PER_DAY`, `API_KEY_RECOGNITIONS_PER_DAY`). Відповіді з кешу (`cached`) денну квоту не витрачають |
| `GET /v1/recognitions/:id`                        | 120 на хвилину                                                                                         |
| `GET /v1/recognitions/:id/events`                 | 120 на хвилину; не більше 5 відкритих потоків на клієнта й 300 на сервер (`retry-after: 10`)            |
| `GET /v1/pages/lookup`                            | 120 на хвилину                                                                                         |
| `GET /v1/transcriptions/:id`, `.../history`       | 120 на хвилину                                                                                         |
| `PATCH /v1/transcriptions/:id/lines`, `POST .../verify` | 30 на хвилину                                                                                    |
| `POST /v1/cite`                                   | 120 на хвилину                                                                                         |
| `GET /v1/search`, `GET /v1/transcriptions/recent` | 60 на хвилину                                                                                          |
| `POST /v1/explain`                                | 10 на хвилину; 100 на добу для гостя (змінюється параметром сервера)                                    |
| `POST /v1/chat`                                   | 10 на хвилину; 50 на добу для гостя (змінюється параметром сервера)                                     |
| `POST /api/auth/email-otp/send-verification-otp`  | 3 листи на пару «адреса пошти + клієнт» і 10 на адресу за 15 хвилин; 300 листів на добу на весь сервер (`SIGN_IN_CODES_PER_DAY`) |
| `POST /v1/admin/*`, `GET /v1/admin/stats`, `GET /health` | ліміту частоти немає                                                                           |

Ліміти за хвилину рахуються за адресою клієнта (див. розділ про гостя), окрім `POST /v1/recognitions`, де для ключа API лічильник ведеться за ключем.

Денні квоти скидаються за добовим вікном; `retry-after` у такій відповіді показує, скільки секунд лишилося.

### 503

| `error.code`         | Де                                                  | Значення                                                                                             |
| -------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `shutting_down`      | будь-який маршрут                                   | Сервер зупиняється. Заголовок `retry-after: 5`; повторіть запит за кілька секунд. Для `POST /v1/recognitions` така сама відповідь буває, коли черга вже закрита |
| `reader_unavailable` | `POST /v1/recognitions`                             | Читання недоступне: не налаштовано модель, вичерпано добовий бюджет викликів моделі, і готового результату в кеші немає |
| `reader_unavailable` | `POST /v1/explain`, `POST /v1/chat`                 | Модель недоступна або бюджет вичерпано (повідомлення відрізняються: «Пояснення тимчасово недоступне», «Чат тимчасово недоступний») |
| (без `error`)        | `GET /health`                                       | База даних не відповіла; тіло — об'єкт стану (див. [Health](#health))                                |

### Інші відмови, пов'язані з обсягом

- `413 too_large` — тіло запиту більше за ліміт маршруту: розпізнавання 12 МіБ; редагування рядків 256 КіБ; пояснення, чат — 32 КіБ; цитата — 1 КіБ; адмін — 2 МіБ. Також `413`, якщо PNG-зображення після декодування більше за 7 МіБ.

## Спільні типи

Нижче — об'єкти, що повторюються в різних маршрутах (схеми в `packages/contracts/src/common.ts`, `recognitions.ts`, `search.ts`).

### Shelfmark (шифр)

| Поле        | Тип                       | Обмеження                                                                                       |
| ----------- | ------------------------- | ----------------------------------------------------------------------------------------------- |
| `archive`   | string                    | обов'язкове; після обрізання пробілів 1–64 символи, без керівних символів                         |
| `fond`      | string                    | те саме                                                                                         |
| `opys`      | string                    | те саме                                                                                         |
| `sprava`    | string                    | те саме                                                                                         |
| `folio`     | string                    | необов'язкове; те саме                                                                          |
| `image`     | integer                   | необов'язкове; 1–100000                                                                         |
| `portal`    | `"archium"` \| `"own"`    | необов'язкове                                                                                   |
| `portalUrl` | string (http/https URL)   | необов'язкове; до 2048 символів, без логіна й пароля в адресі, без керівних символів            |

У запитах, де шифр є вхідним (`POST /v1/recognitions`), потрібне хоча б одне з `folio` та `image`.

### Box

`{ "x": 0..1, "y": 0..1, "w": 0..1, "h": 0..1 }`; `w` і `h` більші за 0, `x + w` і `y + h` не виходять за 1 (допуск `1.000001`).

### Line (рядок транскрипції)

| Поле        | Тип                          | Значення                                                              |
| ----------- | ---------------------------- | --------------------------------------------------------------------- |
| `idx`       | integer ≥ 0                  | номер рядка                                                            |
| `text`      | string                       | текст рядка                                                            |
| `box`       | Box                          | положення рядка                                                        |
| `boxSource` | `"model"` \| `"estimated"`   | `estimated` означає, що рамку оцінено за порядком рядків, а не виміряно: показуйте її смугою, не точною рамкою |
| `uncertain` | boolean                      | модель сумнівається хоча б в одному слові рядка                         |
| `words`     | `{ text, uncertain, confidence? }[]` | слова; `confidence` — 0..1, необов'язкове                       |

### Transcription (версія транскрипції)

| Поле               | Тип                                  | Значення                                                                                  |
| ------------------ | ------------------------------------ | ----------------------------------------------------------------------------------------- |
| `id`               | uuid                                 | ідентифікатор версії                                                                       |
| `regionId`         | uuid                                 | фрагмент зображення, до якого належать усі версії                                          |
| `shelfmark`        | Shelfmark                            | є, якщо фрагмент прив'язано до сторінки                                                    |
| `box`              | Box                                  | рамка фрагмента на зображенні                                                              |
| `version`          | integer ≥ 1                          | номер версії в межах фрагмента                                                             |
| `status`           | `draft` \| `verified` \| `disputed`  | стан                                                                                       |
| `lines`            | Line[]                               | прочитані рядки                                                                            |
| `normalizedText`   | string                               | нормалізований текст                                                                       |
| `normalizedLines`  | `{ text, words }[]`                  | необов'язкове                                                                              |
| `expansions`       | `{ from, to }[]`                     | розкриття скорочень; необов'язкове                                                         |
| `translatedLines`  | string[]                             | сучасний переклад, по одному рядку на кожен `lines[i]`; необов'язкове                       |
| `entities`         | `{ type, text, start, end, normalized?, wikidataId?, extra? }[]` | `type`: `person`, `place`, `term`, `date`            |
| `warnings`         | string[]                             | `cut_off_left`, `cut_off_right`, `cut_off_top`, `cut_off_bottom`, `damaged_paper`, `faint_ink`; необов'язкове |
| `reader`           | string                               | назва читача (модель) або `fixture` у тестовому режимі                                      |
| `author`           | `{ name }`                           | автор останньої правки; необов'язкове                                                       |
| `verifiedBy`       | `{ name }`                           | необов'язкове                                                                              |
| `verifiedSignature`| string                               | підпис підтвердження; необов'язкове                                                         |
| `verifiedAt`       | ISO datetime                         | необов'язкове                                                                              |
| `createdAt`        | ISO datetime                         |                                                                                            |

Редагування рядків створює нову версію з новим `id` і зростаючим `version`; стара версія не змінюється.

### Курсорна пагінація

`GET /v1/search` і `GET /v1/transcriptions/recent` повертають `nextCursor`, якщо є наступна сторінка. Передайте його як `cursor` у наступному запиті з тими самими іншими параметрами. Курсор непрозорий (не розбирайте його); некоректний дає `400 bad_request`.

## Розпізнавання

### POST /v1/recognitions

Ставить у чергу розпізнавання зображення фрагмента або одразу віддає готовий результат з кешу.

- Автентифікація: гість або ключ API (див. [Ключ API](#ключ-api)).
- Обмеження тіла: 12 МіБ.

Тіло запиту:

| Поле        | Тип                                              | Обов'язкове | Обмеження                                                                                                        |
| ----------- | ------------------------------------------------ | ----------- | ---------------------------------------------------------------------------------------------------------------- |
| `image`     | `{ base64Png: string }`                          | так         | PNG у base64, не порожній; після декодування до 7 МіБ, сторона до 8000 пікселів, до 50 млн пікселів загалом        |
| `imageHash` | string                                           | так         | SHA-256 від байтів PNG, 64 символи `a-f0-9` (нижній регістр); має збігатися з хешем зображення                    |
| `source`    | `extension` \| `web` \| `mcp` \| `batch`         | так         | звідки прийшов запит                                                                                             |
| `shelfmark` | Shelfmark                                        | ні          | потрібне `folio` або `image`                                                                                     |
| `box`       | Box                                              | ні          | положення фрагмента на сторінці; без нього береться вся сторінка `{x:0,y:0,w:1,h:1}`                              |
| `hints`     | `{ language?, period?, documentType? }`          | ні          | `language`: `uk`, `ru`, `church-slavonic`, `pl`; `period`: `17`, `18`, `19`, `20`; `documentType`: `metric`, `revision`, `court`, `other` |
| `document`  | `{ yearFrom, yearTo }`                           | ні          | роки 1000–2100, `yearFrom <= yearTo`; зберігається лише для запитів із ключем API                                  |

Дедуплікація: фрагмент ідентифікується за `imageHash`. Якщо для нього вже є транскрипція, сервер відповідає `status: "cached"` з `transcriptionId`, не викликаючи модель. Якщо розпізнавання того самого фрагмента вже триває, повертається його `recognitionId` зі `status: "queued"`.

Успішна відповідь: `201 Created`.

| Поле              | Тип                      | Значення                                                       |
| ----------------- | ------------------------ | -------------------------------------------------------------- |
| `recognitionId`   | uuid                     | ідентифікатор задачі                                            |
| `status`          | `queued` \| `cached`     | `queued` — задачу поставлено (або вона вже виконується); `cached` — результат готовий |
| `transcriptionId` | uuid                     | лише для `cached`                                               |

Помилки:

| HTTP | `error.code`         | Умова                                                                                     |
| ---- | -------------------- | ----------------------------------------------------------------------------------------- |
| 400  | `bad_request`        | тіло не пройшло схему                                                                      |
| 400  | `bad_image`          | не PNG, недопустимі розміри або `imageHash` не збігається із зображенням                    |
| 401  | `unauthorized`       | невідомий ключ API (`khr_...`)                                                              |
| 413  | `too_large`          | тіло понад 12 МіБ або зображення понад 7 МіБ                                                |
| 429  | `too_many_requests`  | ліміт частоти, забагато одночасних розпізнавань, черга заповнена, вичерпано денну квоту або забагато спроб із невідомим ключем |
| 503  | `reader_unavailable` | читання недоступне й готового результату немає                                              |
| 503  | `shutting_down`      | сервер перезапускається                                                                    |

Приклад:

```bash
HASH=$(sha256sum fragment.png | cut -d' ' -f1)
jq -n --arg img "$(base64 -w0 fragment.png)" --arg hash "$HASH" '{
  image: { base64Png: $img },
  imageHash: $hash,
  source: "batch",
  shelfmark: { archive: "ЦДІАК", fond: "127", opys: "1012", sprava: "5", folio: "12" },
  hints: { language: "ru", period: "18" }
}' > body.json

  -H 'content-type: application/json' \
  -H "authorization: Bearer $KHRONIST_API_KEY" \
  --data-binary @body.json
```

Заголовок `authorization` можна пропустити, щоб працювати як гість. Відповідь:

```json
{
  "recognitionId": "0192f3a8-6b1c-7d4e-9a2f-3c5b8e1d4a70",
  "status": "queued"
}
```

### GET /v1/recognitions/:id/events

Відкриває потік серверних подій (Server-Sent Events) про хід розпізнавання.

- Автентифікація: не потрібна.
- Відповідь: `200 OK`, `content-type: text/event-stream; charset=utf-8`.

Формат кадру: `event: <назва>`, `data: <JSON>`, порожній рядок. На початку сервер надсилає `retry: 3000`, далі кожні 15 секунд коментар `: ping`.

| `event`    | `data`                          | Значення                                                          |
| ---------- | ------------------------------- | ----------------------------------------------------------------- |
| `progress` | `{ "status": "<стадія>" }`      | змінилася стадія (`queued`, `reading`, `normalizing`, ...)         |
| `line`     | `{ "line": Line }`              | прочитано рядок                                                    |
| `done`     | `{ "transcriptionId": "<uuid>" }` | результат збережено; потік закривається                         |
| `failed`   | `{ "code": "...", "message": "..." }` | помилка; потік закривається                                 |

Для вже завершеного розпізнавання сервер одразу відтворює події `line` для кожного рядка і `done` (або `failed`). Потік закривається також через 5 хвилин.

Помилки (до відкриття потоку, у звичайному форматі помилки):

| HTTP | `error.code`        | Умова                                                                      |
| ---- | ------------------- | -------------------------------------------------------------------------- |
| 400  | `bad_request`       | `id` не є uuid                                                              |
| 404  | `not_found`         | розпізнавання не існує                                                      |
| 429  | `too_many_requests` | понад 5 відкритих потоків з однієї адреси, 300 на сервері (`retry-after: 10`) або понад 120 запитів за хвилину |

Приклад (`-N` вимикає буферизацію):

```bash
curl -sS -N https://api.khronist.org/v1/recognitions/0192f3a8-6b1c-7d4e-9a2f-3c5b8e1d4a70/events
```

```text

data: {"status":"reading"}

event: done
data: {"transcriptionId":"0192f3a8-9d20-7a3b-8c41-5e7f2a6b9c13"}

```

### PATCH /v1/transcriptions/:id/lines

Виправляє текст окремих рядків. Створює нову версію транскрипції; після цього сервер у фоні заново нормалізує текст, шукає сутності й переклад для нової версії.

- Автентифікація: сесія (`401 unauthorized` без неї).
- Обмеження тіла: 256 КіБ.
- Параметри шляху: `id` — uuid версії, яку правлять; це має бути остання версія фрагмента.

Тіло запиту:

| Поле               | Тип                     | Обов'язкове | Обмеження                                                                                         |
| ------------------ | ----------------------- | ----------- | ------------------------------------------------------------------------------------------------- |
| `baseVersion`      | integer ≥ 1             | так         | номер версії, на основі якої зроблено правку; має збігатися з `version` версії `id`                 |
| `lines`            | `{ idx, text }[]`       | так         | від 1 до 200 елементів, `idx` не повторюються                                                      |
| `lines[].idx`      | integer ≥ 0             | так         | номер рядка, що існує в цій версії                                                                 |
| `lines[].text`     | string                  | так         | до 500 символів, без переносів рядка (`\r`, `\n`, U+2028, U+2029), без NUL і непарних сурогатів    |

Успішна відповідь: `200 OK`, об'єкт Transcription. Якщо жоден рядок не змінився (`text` збігається з наявним), нової версії не створюється й повертається поточна. Інакше повертається нова версія (інший `id`, `version` на одиницю більший, `status: "draft"`, `author` — поточний користувач).

Помилки:

| HTTP | `error.code`         | Умова                                                                                      |
| ---- | -------------------- | ------------------------------------------------------------------------------------------ |
| 400  | `bad_request`        | тіло не пройшло схему; у версії немає рядка з таким `idx`                                   |
| 401  | `unauthorized`       | немає сесії                                                                                 |
| 404  | `not_found`          | версії немає                                                                                |
| 409  | `version_conflict`   | `baseVersion` не збігається з версією `id`, або `id` не остання версія фрагмента             |
| 413  | `too_large`          | тіло понад 256 КіБ                                                                          |
| 429  | `too_many_requests`  | понад 30 запитів за хвилину                                                                 |

Відповідь `409` має додаткове поле `current` з актуальною версією (Transcription):

```json
{
  "error": {
    "code": "version_conflict",
    "message": "Транскрипцію вже змінили, ось поточна версія"
  },
  "current": { "id": "…", "version": 2, "…": "повний об'єкт Transcription" }
}
```

Приклад:

```bash
curl -sS -X PATCH \
  https://api.khronist.org/v1/transcriptions/0192f3a8-9d20-7a3b-8c41-5e7f2a6b9c13/lines \
  -H 'content-type: application/json' \
  -H "authorization: Bearer $SESSION_TOKEN" \
  -d '{"baseVersion":1,"lines":[{"idx":0,"text":"Року 1751"}]}'
```

Відповідь — повний об'єкт Transcription нової версії (формат як у [GET /v1/transcriptions/:id](#get-v1transcriptionsid)).

## Підтвердження

### POST /v1/transcriptions/:id/verify

Позначає версію як підтверджену людиною (`status: "verified"`). Підтверджені версії потрапляють у відкритий шар Commons.

- Автентифікація: сесія користувача, пошта якого входить до `VERIFIER_EMAILS` (порівняння без урахування регістру).
- Параметри шляху: `id` — uuid версії; має бути остання версія фрагмента.

Тіло запиту (об'єкт; якщо додаткових даних немає, надсилайте `{}`):

| Поле        | Тип    | Обов'язкове | Обмеження                                                                                                   |
| ----------- | ------ | ----------- | ----------------------------------------------------------------------------------------------------------- |
| `signature` | string | ні          | після обрізання пробілів 1–80 символів, без керівних символів і непарних сурогатів                           |
| `portalUrl` | string | ні          | адреса зображення в переглядачі архіву: `https://archium.cdiak.archives.gov.ua/file-viewer/<число>` (за потреби з `#file-<число>`); записується до сторінки, лише якщо в неї ще немає адреси |

Повторне підтвердження вже підтвердженої версії не змінює її (повертається та сама версія).

Успішна відповідь: `200 OK`, об'єкт Transcription зі `status: "verified"`, `verifiedBy`, `verifiedAt` і, якщо передано, `verifiedSignature`.

Помилки:

| HTTP | `error.code`         | Умова                                                           |
| ---- | -------------------- | --------------------------------------------------------------- |
| 400  | `bad_request`        | тіло не пройшло схему                                            |
| 401  | `unauthorized`       | немає сесії                                                      |
| 403  | `forbidden`          | користувач не входить до списку тих, хто може підтверджувати     |
| 404  | `not_found`          | версії немає                                                     |
| 409  | `version_conflict`   | `id` не остання версія фрагмента; у відповіді є поле `current`   |
| 429  | `too_many_requests`  | понад 30 запитів за хвилину                                      |

Приклад:

```bash
curl -sS -X POST \
  https://api.khronist.org/v1/transcriptions/0192f3a8-9d20-7a3b-8c41-5e7f2a6b9c13/verify \
  -H 'content-type: application/json' \
  -H "authorization: Bearer $SESSION_TOKEN" \
  -d '{"signature":"Олена К., історикиня"}'
```

Відповідь — повний об'єкт Transcription зі `status: "verified"`.

## Commons: пошук і стрічка

### GET /v1/search

Повнотекстовий пошук по транскрипціях відкритого шару (для кожного фрагмента береться найкраща версія: підтверджена, а серед них новіша). Запит розширюється синонімами зі словника, імена шукаються з урахуванням близькості написання.

- Автентифікація: не потрібна.

Параметри запиту:

| Параметр       | Тип                | Обов'язковий | Обмеження                                                                    |
| -------------- | ------------------ | ------------ | ---------------------------------------------------------------------------- |
| `q`            | string             | так          | після обрізання пробілів 1–200 символів                                       |
| `archive`      | string             | ні           | точний збіг                                                                   |
| `fond`         | string             | ні           | точний збіг                                                                   |
| `yearFrom`     | integer            | ні           | 1000–2100; відбираються справи, що закінчуються не раніше цього року            |
| `yearTo`       | integer            | ні           | 1000–2100; відбираються справи, що починаються не пізніше цього року            |
| `verifiedOnly` | boolean            | ні           | `true` — лише підтверджені                                                    |
| `limit`        | integer            | ні           | 1–50, за замовчуванням 20                                                     |
| `cursor`       | string             | ні           | `nextCursor` з попередньої відповіді                                           |

Якщо `yearFrom` більший за `yearTo`, відповідь — порожній список.

Успішна відповідь: `200 OK`.

| Поле         | Тип                                                                                                   | Значення                                                          |
| ------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `items`      | `{ transcriptionId, shelfmark, yearFrom?, yearTo?, snippet, status, portalUrl? }[]`                   | у порядку спадання релевантності                                   |
| `nextCursor` | string                                                                                                | є, якщо результатів більше за `limit`                              |

Помилки:

| HTTP | `error.code`        | Умова                                       |
| ---- | ------------------- | ------------------------------------------- |
| 400  | `bad_request`       | параметри не пройшли схему; некоректний `cursor` |
| 429  | `too_many_requests` | понад 60 запитів за хвилину                  |

Приклад:

```bash
curl -sS -G https://api.khronist.org/v1/search \
  --data-urlencode 'q=Коваленко' \
  --data-urlencode 'verifiedOnly=true' \
  --data-urlencode 'limit=5'
```

## Пояснення й чат

Обидва маршрути відповідають лише на підставі джерел корпусу (і, для чату, прив'язаного запису). Якщо підтверджених джерел немає, `answer` дорівнює `null`, а `reason` — `no_sources`; це не помилка. Кожне посилання в `citations` містить дослівну цитату, перевірену на наявність у джерелі.

### POST /v1/explain

Пояснює термін, місце, дату або сутність із посиланнями на джерела.

- Автентифікація: не потрібна (гостьові ліміти).
- Обмеження тіла: 32 КіБ.

Тіло запиту:

| Поле                       | Тип                                         | Обов'язкове | Обмеження                                    |
| -------------------------- | ------------------------------------------- | ----------- | -------------------------------------------- |
| `kind`                     | `term` \| `place` \| `date` \| `entity`     | так         |                                              |
| `text`                     | string                                      | так         | після обрізання пробілів 1–200 символів       |
| `context.transcriptionId`  | uuid                                        | ні          | запис, у якому зустрілося слово               |
| `context.period`           | `17` \| `18` \| `19` \| `20`                | ні          | століття                                      |

Успішна відповідь: `200 OK`.

| Поле         | Тип                                                                                   | Значення                                                                                     |
| ------------ | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `answer`     | string \| null                                                                        | пояснення або `null`                                                                          |
| `reason`     | `"no_sources"`                                                                        | є, коли відповіді немає через брак джерел                                                     |
| `confidence` | `high` \| `low`                                                                       | є, коли є відповідь                                                                           |
| `citations`  | `{ kind: "chunk", chunkId, sourceId, title, url?, licence, retelling, quote }[]`      | джерела; порожній, коли `answer` — `null`                                                     |
| `place`      | `{ modernName, region, wikidataId }`                                                  | необов'язкове                                                                                 |
| `date`       | `{ julian, gregorian, weekday }`                                                      | для `kind: "date"`, якщо дату вдалося розібрати; повертається навіть коли моделі недоступні   |

Помилки:

| HTTP | `error.code`         | Умова                                                                       |
| ---- | -------------------- | --------------------------------------------------------------------------- |
| 400  | `bad_request`        | тіло не пройшло схему                                                        |
| 413  | `too_large`          | тіло понад 32 КіБ                                                            |
| 429  | `too_many_requests`  | понад 10 запитів за хвилину або вичерпано денну квоту                         |

Приклад:

```bash
curl -sS -X POST https://api.khronist.org/v1/explain \
  -H 'content-type: application/json' \
  -d '{"kind":"term","text":"ревізія","context":{"period":"18"}}'
```


## Вхід і профіль

Ці маршрути обслуговує бібліотека better-auth через тонку обгортку; вони живуть під `/api/auth/`, не під `/v1`. Доступні лише коли на сервері налаштовано вхід (див. [Наявність маршрутів](#наявність-маршрутів-залежить-від-налаштувань-сервера)). Кожне тіло, що надходить, перевіряється Zod-схемою.

Помилки цієї групи мають стандартний формат. Окрім загальних кодів, сервер повертає:

| HTTP | `error.code`         | Коли                                                       |
| ---- | -------------------- | ---------------------------------------------------------- |
| 400  | `invalid_otp`        | невірний код                                                |
| 400  | `otp_expired`        | код прострочено                                             |
| 400  | `too_many_attempts`  | забагато невдалих спроб, потрібен новий код                  |
| 403  | `invalid_origin`     | `Origin` запиту недовірений                                 |
| 429  | `too_many_requests`  | ліміти листів і спроб (див. розділ про ліміти)               |

Інші помилки бібліотеки зводяться до загальних кодів за статусом (`bad_request`, `unauthorized`, `forbidden`, `not_found`), а помилки 5xx — до `internal_error`. Маршрути бібліотеки, яких немає в цьому розділі (наприклад, видалення користувача), вимкнено й відповідають `404 not_found`.

### POST /api/auth/email-otp/send-verification-otp

Надсилає на пошту одноразовий шестицифровий код для входу.

- Автентифікація: не потрібна.

Тіло запиту:

| Поле    | Тип                | Обов'язкове | Обмеження             |
| ------- | ------------------ | ----------- | --------------------- |
| `email` | string (email)     | так         | до 254 символів        |
| `type`  | `"sign-in"`        | так         | лише це значення       |

Успішна відповідь: `200 OK`. Тіло формує бібліотека (`{ "success": true }` у встановленій версії better-auth 1.7.23); лист надсилається у фоні, тому успіх не гарантує доставки.

Помилки: `400 bad_request` (тіло не пройшло схему), `403 invalid_origin`, `429 too_many_requests` (3 листи на пару «адреса + клієнт» і 10 на адресу за 15 хвилин, 300 на добу на весь сервер; `retry-after` у секундах). Адреси Gmail зіставляються без крапок і без частини після `+`.

Приклад:

```bash
curl -sS -X POST https://api.khronist.org/api/auth/email-otp/send-verification-otp \
  -H 'content-type: application/json' \
  -d '{"email":"researcher@example.org","type":"sign-in"}'
```

### GET /api/auth/get-session

Повертає поточну сесію.

- Автентифікація: сесія (токен або cookie); без неї це не помилка.

Успішна відповідь: `200 OK`. Без чинної сесії тіло — `null`. Інакше — об'єкт, що відповідає схемі `sessionResponseSchema`:

| Поле        | Тип                              | Значення                                                          |
| ----------- | -------------------------------- | ----------------------------------------------------------------- |
| `user`      | `{ id, email, name }`            | `name` — підпис користувача для підтверджень; порожній, поки не задано |
| `canVerify` | boolean                          | чи може користувач підтверджувати (`POST .../verify`)              |

Сервер додає до цього об'єкта й технічні поля бібліотеки (наприклад `session`); покладатися слід лише на `user` і `canVerify`.

Приклад:

```bash
curl -sS https://api.khronist.org/api/auth/get-session \
  -H "authorization: Bearer $SESSION_TOKEN"
```

```json
{
  "user": { "id": "u_01", "email": "researcher@example.org", "name": "Олена К." },
  "canVerify": false
}
```

## Адмін: корпус і словник

Маршрути наповнення корпусу знань (джерела, фрагменти, синоніми) і зведення статистики. Усі вимагають ключ адміністратора (`Authorization: Bearer <ADMIN_API_KEY>`); без нього або з хибним ключем — `401 unauthorized`. Обмеження тіла для записів — 2 МіБ (`413 too_large`). Записи в `chunks` і `synonyms` серіалізуються між собою на сервері, тому паралельні виклики виконуються по черзі.

### POST /v1/admin/sources

Додає або оновлює джерела за `url` (ідемпотентно).

Тіло запиту: `{ "items": [...] }`, не менше одного елемента; повторні `url` в одному запиті — береться останній.

| Поле (елемент)          | Тип                                                                   | Обмеження                                              |
| ----------------------- | --------------------------------------------------------------------- | ------------------------------------------------------ |
| `url`                   | string (https URL)                                                    | лише `https`, без керівних символів                     |
| `title`                 | string                                                                | після обрізання не порожній, без NUL і непарних сурогатів |
| `licence`               | `суспільне надбання` \| `CC BY-SA 4.0`                                |                                                        |
| `kind`                  | `dictionary` \| `encyclopedia` \| `wikidata` \| `publication`         |                                                        |
| `periodFrom`, `periodTo`| integer                                                               | століття 1–21, `periodFrom <= periodTo`                 |

Успішна відповідь: `200 OK`, `{ "items": [{ "id": uuid, "url": string }] }`.

Помилки: `400 bad_request`, `401 unauthorized`, `413 too_large`.

Приклад:

```bash
curl -sS -X POST https://api.khronist.org/v1/admin/sources \
  -H 'content-type: application/json' \
  -H "authorization: Bearer $ADMIN_API_KEY" \
  -d '{"items":[{"url":"https://example.org/dictionary","title":"Словник","licence":"суспільне надбання","kind":"dictionary","periodFrom":18,"periodTo":19}]}'
```

```json
{
  "items": [{ "id": "0192f3a8-3333-7444-8555-666677778888", "url": "https://example.org/dictionary" }]
}
```

### POST /v1/admin/chunks

Синхронізує фрагменти корпусу. Це повна синхронізація: фрагменти, яких немає в запиті, видаляються з бази. Щоб не втратити корпус, надсилайте весь набір фрагментів за один запит.

Тіло запиту: `{ "items": [...] }`, не менше одного елемента; пара `articleKey` + `idx` не повторюється.

| Поле (елемент)           | Тип                                           | Обмеження                                                    |
| ------------------------ | --------------------------------------------- | ------------------------------------------------------------ |
| `articleKey`             | string                                        | `^[a-z0-9]+(-[a-z0-9]+)*$`                                    |
| `idx`                    | integer ≥ 0                                   | номер фрагмента в статті                                      |
| `sourceId`               | uuid                                          | ідентифікатор джерела з `POST /v1/admin/sources`              |
| `text`, `topic`          | string                                        | після обрізання не порожні, без NUL і непарних сурогатів      |
| `type`                   | `term` \| `place` \| `date` \| `unit` \| `abbr` |                                                            |
| `periodFrom`, `periodTo` | integer                                       | століття 1–21, `periodFrom <= periodTo`                       |
| `wikidataId`             | string                                        | необов'язкове; `^Q[1-9][0-9]*$`                                |

Успішна відповідь: `200 OK`, `{ "inserted", "updated", "unchanged", "deleted" }` — цілі числа ≥ 0.

Помилки: `400 bad_request` (також «Невідоме джерело чанка», якщо `sourceId` не існує), `401 unauthorized`, `413 too_large`.

Приклад:

```bash
curl -sS -X POST https://api.khronist.org/v1/admin/chunks \
  -H 'content-type: application/json' \
  -H "authorization: Bearer $ADMIN_API_KEY" \
  -d '{"items":[{"articleKey":"revizia","idx":0,"sourceId":"0192f3a8-3333-7444-8555-666677778888","text":"Текст статті","topic":"Ревізія","type":"term","periodFrom":18,"periodTo":19}]}'
```

```json
{ "inserted": 1, "updated": 0, "unchanged": 0, "deleted": 0 }
```

### POST /v1/admin/synonyms

Додає або оновлює словник синонімів і варіантів написання, який використовує пошук.

Тіло запиту: `{ "items": [...] }`, не менше одного елемента; пара `term` + `variant` в одному запиті — береться остання.

| Поле (елемент) | Тип    | Обмеження                                                  |
| -------------- | ------ | ---------------------------------------------------------- |
| `term`         | string | після обрізання не порожній, без NUL і непарних сурогатів   |
| `variant`      | string | те саме                                                     |
| `type`         | string | те саме                                                     |

Успішна відповідь: `200 OK`, `{ "inserted", "updated", "unchanged" }` — цілі числа ≥ 0.

Помилки: `400 bad_request`, `401 unauthorized`, `413 too_large`.

Приклад:

```bash
curl -sS -X POST https://api.khronist.org/v1/admin/synonyms \
  -H 'content-type: application/json' \
  -H "authorization: Bearer $ADMIN_API_KEY" \
  -d '{"items":[{"term":"ревізія","variant":"ревизія","type":"variant"}]}'
```

```json
{ "inserted": 1, "updated": 0, "unchanged": 0 }
```

## Health

### GET /health

Перевіряє, чи працює сервер і база даних. Маршрут без префікса `/v1`, без автентифікації й без ліміту частоти; використовується для моніторингу.

Відповідь має однакову форму для `200` і `503`:

| Поле  | Тип                                                | Значення                                                                 |
| ----- | -------------------------------------------------- | ------------------------------------------------------------------------ |
| `ok`  | boolean                                            | `true`, якщо база відповіла                                               |
| `db`  | `ok` \| `down`                                     | стан бази (перевірка має таймаут 2 секунди)                                |
| `llm` | `ok` \| `degraded`                                 | `degraded`, якщо для основної текстової моделі немає ключа провайдера     |
| `htr` | `vision` \| `remote` \| `fixture` \| `down`        | який читач активний; `down` — читача немає, розпізнавання повертатиме `503 reader_unavailable` |

HTTP-код: `200`, коли база доступна, і `503`, коли ні (тіло при цьому не у форматі помилки, а такий самий об'єкт стану з `ok: false`, `db: "down"`). Під час зупинки сервера відповідь — `503 shutting_down` у стандартному форматі помилки.

Приклад:

```bash
curl -sS https://api.khronist.org/health
```

```json
{ "ok": true, "db": "ok", "llm": "ok", "htr": "vision" }
```

## Асинхронні задачі

Єдина тривала операція — розпізнавання (`POST /v1/recognitions`). Запит повертається одразу (`201`), а читання виконується у фоні в процесі сервера.

Послідовність:

1. `POST /v1/recognitions` повертає `recognitionId` і `status`.
   - `cached` — результат уже є; його `transcriptionId` у відповіді. Забирайте транскрипцію через `GET /v1/transcriptions/:id`; опитування не потрібне.
   - `queued` — задачу поставлено (або вона вже виконується для цього зображення).
2. Стежте за ходом одним із двох способів:
   - потік подій `GET /v1/recognitions/:id/events` (рекомендовано, дає рядки в міру читання; закривається після `done` або `failed`, не довше 5 хвилин, тож після обриву підключіться знову);
   - опитування `GET /v1/recognitions/:id`: повторюйте запит, доки `status` не стане `done` або `failed`. Рекомендований інтервал код не задає; пам'ятайте про ліміт 120 запитів за хвилину.
3. Стадії за порядком: `queued`, `reading`, `normalizing`, потім `done` або `failed`.
4. При `done` у відповіді `GET /v1/recognitions/:id` є `transcription`, а подія `done` містить `transcriptionId`.
5. При `failed` є `error.code` (`read_failed`, `no_text`, `normalize_failed`, `restarted`, `bad_image`, `too_large`, `save_failed`) і `message`. Код `restarted` означає, що сервер перезапустився під час задачі або задача зависла понад 10 хвилин: надішліть запит ще раз.

Поки перелік вище працює, повторний `POST` із тим самим зображенням не створює дубль: повертається той самий `recognitionId`, а коли результат уже є, відповідь — `cached`.
