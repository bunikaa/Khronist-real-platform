# 04 · ML, частина 1: читання рукопису

Відповідальні: Анна Бондаренко, Катерина Мех. Цей документ написано так, щоб його можна було виконати покроково разом з AI-асистентом; інструкції для асистента — у `08-ai-instructions.md`.

## 1. Задача

Отримати фрагмент скану (PNG, 10–15 рядків) і повернути текст рядок за рядком із позначками непевних слів. Два треки з одним контрактом виходу (`07-contracts.md`, розділ 1, тип `Line`):

- **Трек A (must, з 5 листопада):** мультимодальна модель через API (Claude основна, Gemini резерв) за промптом `htr_vision`. Координати рядків модель не дає; API ядра малює рівні смуги (`boxSource: 'estimated'`).
- **Трек B (should, старт не раніше 9 листопада і лише якщо трек A стабільний):** Rukopys-OCR-4B на Modal за контрактом `POST /recognize` (`07`, розділ 3), з реальними координатами рядків. Перемикається в проді однією змінною `HTR_URL`, якщо до вечора 17 листопада CER на золотому наборі кращий за трек A щонайменше на 3 відсоткові пункти й теплий виклик укладається в 8 с.

Ціль для слайда — чесна цифра CER на золотому наборі з датою і складом набору, не округлена в кращий бік.

## 4. Трек A покроково

### Крок 1 · Тест здійсненності (1–3 листопада)
1. Узяти 10 аркушів демо-фонду (список від Дарії). Вирізати по 2–3 фрагменти з кожного, масштабувати до ширини 1200–1600 px.
2. `feasibility.py`: прогнати кожен фрагмент через Claude і Gemini із зображенням і промптом «Transcribe this handwritten 19th-century church record from a Ukrainian archive line by line. Keep the original orthography, including ѣ, і, ъ, ѳ. Return one line per text line. Mark words you are unsure about.» За можливості — той самий фрагмент через веб-демо Rukopys OCR для порівняння очима.
3. Заповнити таблицю: фрагмент, модель, «читається / частково / ні», помітки про почерк. Записати в `docs/htr-feasibility.md`. Це вхід для гейту 0.

### Крок 2 · Промпт `htr_vision` v0 (5 листопада)
Structured output за `schema.json`:
```json
{ "lines": [ { "text": "Села Борщаговки крестьянинъ Іоаннъ", "words": [ { "text": "Села", "uncertain": false }, { "text": "Іоаннъ", "uncertain": true } ] } ], "warnings": ["cut_off_right"] }
```
Правила в `system.md`: зберігати орфографію оригіналу, не нормалізувати, не додавати слова, не пропускати рядків, переноси позначати дефісом у кінці рядка, нерозбірливе — `[нрзб]`, `uncertain: true` для слів, у яких модель сумнівається. У `README.md` — як масштабувати зображення, які `hints` (мова, період, тип документа) підставляються в `user.md`.

### Крок 3 · Золотий набір і перший CER (6–7 листопада, разом з Дарією)
1. Історик транскрибує 30–50 рядків із 5–8 аркушів у `eval/gold/lines.jsonl`: `{"image": "p14.png", "idx": 1, "text": "Села Борщаговки крестьянинъ…"}`. Координати не потрібні для треку A.
2. `run_htr_eval.py`: для кожної моделі — CER і WER загалом і по аркушах, таблиця найчастіших плутанин (ѣ/е, і/и, ъ, титла), час на фрагмент, вартість за `usage`.
3. Звіт у `eval/results/2026-11-14-htr.md`.

### Крок 4 · Вибір моделі й калібрування непевності (8 листопада)
- Основна модель читання — та, що дає менший CER при часі ≤ 10 с; записати в `docs/decisions.md` і передати Владиславу значення `HTR_MODEL_PRIMARY` / `HTR_MODEL_FALLBACK`.
- Калібрування позначок: на золотому наборі порівняти слова з `uncertain: true` з реальними помилками. Ціль — ловити не менше 70 % помилкових слів при не більш ніж 30 % хибних спрацювань. Якщо модель позначає замало — додати в промпт інструкцію позначати слова з нетиповим написанням імен і топонімів; якщо забагато — приклади в `examples.jsonl`.
- Записати частку непевних слів: це чесна цифра для слайда разом із CER.

### Крок 5 · Підказки й друге вимірювання (12–13 листопада)
Після реальних сканів через розширення: додати в `user.md` змінні `hints` (тип документа, період, типові імена повіту зі словника), повторити `run_htr_eval.py`, записати різницю. Фінальна цифра для слайда — 19 листопада.

### Крок 6 · Пакетна обробка для демо (16 листопада)
`batch_recognize.py` бере список URL аркушів від Дарії, вирізає фрагменти за заданими областями (або всю сторінку смугами по 12–15 рядків), викликає `POST /v1/recognitions` з `source: "batch"` і API-ключем, чекає завершення, друкує зведення. 50–200 аркушів до вечора 16-го, щоб публічний пошук мав що показати.

## 5. Трек B покроково (лише за рішенням 9 листопада)

1. **Модель.** Знайти репозиторій Rukopys-OCR-4B на Hugging Face, перевірити ліцензію, формат входу й виходу (чи є координати рядків), записати в `MODEL.md`.
2. **Modal.** `uv add modal`, `modal setup`; `modal_app.py`: образ з vLLM, `modal.Volume` для ваг, `@modal.enter()` для завантаження, `@modal.web_endpoint(method="POST")` для `/recognize`, GPU `A10G`, `container_idle_timeout=300`; `keep_warm=1` лише на час тестів і демо. Якщо vLLM не підтримує архітектуру — `transformers` + `AutoModelForVision2Seq`.
3. **Сегментація.** Якщо модель не дає координат — docTR `detection_predictor` або Kraken `segment`, різати на смуги, розпізнавати батчем, збирати відповідь з `boxSource: 'model'`.
4. **Впевненість.** Logprobs токенів з vLLM: впевненість слова = експонента середнього logprob; `uncertain = confidence < поріг`, поріг підібрати на золотому наборі.
5. **Оцінка.** `run_htr_eval.py --htr-url …` на тому ж золотому наборі; порівняти з треком A у звіті з датою.
6. **Рішення 17 листопада.** Перемикати `HTR_URL` у проді лише при виконанні критерію з розділу 1; інакше трек B лишається в беклозі з готовим кодом і звітом.

## 6. Що віддати команді

- `packages/prompts/htr_vision` з прикладами й README.
- Назви моделей для `HTR_MODEL_PRIMARY` / `HTR_MODEL_FALLBACK` і дата рішення.
- Звіти CER із датами і складом золотого набору; фінальна цифра 19 листопада.
- Частка непевних слів і якість позначок (precision/recall на золотому наборі).
- Трек B, якщо був: URL сервісу, ключ, `MODEL.md`, звіт порівняння.

## 7. Ризики й запасні шляхи

| Ризик | Що робимо |
| --- | --- |
| Модель читає погано на обраному фонді | повідомити Дарії до вечора 4 листопада, змінити фонд на розбірливіший почерк |
| Модель нормалізує орфографію всупереч промпту | приклади в `examples.jsonl` з оригінальним написанням; перевірка в `run_htr_eval.py` на частку сучасних літер там, де в еталоні старі |
| Позначки непевності нерелевантні | показувати лише рядкову позначку «модель не впевнена в рядку», якщо точність на словах нижча за 50 % |
| Ліміти API або збій провайдера на демо | резервна модель в адаптері; результати для демо-аркушів уже в Commons (кеш за хешем) |
| Трек B не встигає | не перемикати; на слайді чесно: «читає мультимодальна модель, відкрита українська модель — наступний крок» |
| Вартість | фрагмент ≈ 1 500 вхідних токенів із зображенням + 500 вихідних; 200 аркушів × 3 фрагменти × 3 виклики ≈ $10–20 разом із тестами |
