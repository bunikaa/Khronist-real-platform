# 08 · Інструкції для AI-асистентів

Команда працює з AI-асистентами (Claude Code, Cursor та інші). Щоб вони розуміли контекст і не ламали чужі зони, у монорепо лежать файли інструкцій. Нижче — готові тексти, які треба покласти в репозиторій як є (прибрати лише цей вступ). Файл `AGENTS.md` у корені — копія `CLAUDE.md` для асистентів, які читають цю назву. Повний контекст проєкту для асистентів — `docs/project-context.md` (файл `10` цього комплекту).

## Корінь: `CLAUDE.md`

```markdown
# Хроніст — інструкції для AI-асистентів

Хроніст — AI-компаньйон для дослідників українських архівів: розширення Chrome читає рукописні скани на архівних порталах, пояснює терміни й дати з джерелами, а підтверджені людьми транскрипції потрапляють у відкритий шар Commons (CC BY 4.0). Будуємо MVP до 21 листопада 2026 для Культурного хакатону OBRIO × МУР, трек «Історія». Після 21 листопада в плані нічого немає; відкладене — у `docs/project-context.md`, розділ «Беклог».

Перед роботою прочитай `docs/project-context.md`, `docs/plan/00-overview.md` і `docs/plan/07-contracts.md`. Контракти — джерело правди: код підлаштовується під контракт, а не навпаки. Зміна контракту — окремий PR із погодженням обох сторін.

## Структура
- `apps/api` — Fastify 5, Drizzle, фонові задачі в процесі (власник: Владислав)
- `apps/extension` — WXT, React 19 (Владислав)
- `apps/web` — Vite, React 19 (Владислав)
- `apps/mcp` — MCP-сервер (Владислав)
- `packages/contracts` — Zod-схеми й типи; `packages/ui` — дизайн-система; `packages/prompts` — промпти (ML-команда)
- `services/knowledge` — корпус, словник, оцінка (ML-команда: Анна, Катерина); `services/htr` — трек B на Modal, якщо стартує

## Правила
- Мова коду англійська (імена, коміти), мова інтерфейсу, промптів для користувача й документації — українська.
- Без коментарів у коді; пояснення — у назвах, типах і README теки.
- TypeScript strict, без `any`; Zod на межах. Python 3.12 з типами, ruff, Pydantic на межах.
- Нічого не вигадувати: ні фактів про архіви, ні джерел, ні назв моделей чи версій пакетів. Невідоме — перевірити в документації або npm/PyPI, або спитати й позначити `TODO(перевірити)`.
- Чесні стани в UI: якщо функції немає — немає й кнопки; невпевненість моделі показується, а не ховається; координати `estimated` малюються смугою, а не рамкою.
- Перед кожним комітом: `pnpm lint typecheck test build` (або `uv run ruff check && uv run pytest` у services) — зелені.
- Коміти невеликі, `feat:`/`fix:`/`chore:` англійською, без згадок моделей чи асистентів у повідомленнях, коді й документації.
- Не чіпати чужу зону без потреби: зміни в `services/*` і `packages/prompts` робить ML-команда, в `apps/*` — Владислав. Якщо треба змінити щось у чужій зоні — опиши в PR, не роби мовчки.
- Секрети лише через env; `.env.example` оновлюється разом із новою змінною.
- Рішення й скорочення обсягу фіксуються в `docs/decisions.md` того ж дня.
- Репозиторій приватний до 13 листопада 2026.

## Команди
`pnpm dev` · `pnpm db:migrate` · `pnpm test` · `pnpm --filter extension zip` · у `services/knowledge`: `uv run python eval/run_htr_eval.py` (`scripts/ingest.py` і `eval/run_qa.py` ще не створено)
```

## `apps/api/CLAUDE.md`

```markdown
Читай спочатку `docs/plan/02-backend.md` і `docs/plan/07-contracts.md`.
- Маршрути — у `src/routes/*`, по файлу на ресурс; схеми запитів і відповідей імпортуються з `@khronist/contracts`, не оголошуються локально.
- Будь-яка робота з БД — через Drizzle і `src/db/schema.ts`; нова таблиця = міграція `pnpm db:generate` у тому ж PR.
- Довгі операції (читання, LLM) — тільки у фонових задачах `src/jobs`; маршрут повертає 201 і `recognitionId`; стан задачі — у таблиці `recognitions`, не в пам'яті.
- Читання рукопису — лише через `src/services/htr`; реалізація обирається за `HTR_URL`. LLM — лише через `src/services/llm`; промпти беруться з `@khronist/prompts`, тексти промптів у коді не пишуться.
- Будь-яка відповідь із пояснення або чату без валідних `citations` — це `answer: null`. Цю перевірку робить код, не промпт.
- Пошук по корпусу — повнотекст + `pg_trgm` + `synonyms`; ембедингів не додавати.
- Тести: юніт для `calendar`, `citation`, парсерів, перевірки citations; інтеграційні для маршрутів проти PGlite з фальшивими ридерами й провайдерами (`test/helpers.ts`).
```

Тексти нижче — початкові версії. Актуальні лежать у репозиторії: `CLAUDE.md` у корені й у зонах `apps/api`, `apps/extension`, `packages/prompts`, `services/knowledge`, а `AGENTS.md` вказує на них (рішення 15 листопада).

## Як ставити задачі асистенту (для всіх)

1. Одна задача — один PR. Формулюй як результат: «Додати маршрут `POST /v1/explain` за контрактом розділ 2, з тестом на випадок без джерел», а не «зроби пояснення».
2. Дай асистенту посилання на потрібний розділ плану й контракту; не передруковуй контракт у чат — він змінюється.
3. Проси показати план перед кодом для задач понад годину.
4. Вимагай запуску перевірок (`pnpm test`, `ruff`, `pytest`) і цитування їхнього виводу.
5. Для ML: проси таблицю результатів, а не прикметники («CER 11,8 % на 42 рядках», а не «працює добре»).
6. Якщо асистент пропонує бібліотеку — попроси версію з npm або PyPI і дату перевірки.
7. Усе, що асистент не зміг перевірити, має бути позначено `TODO(перевірити)` і потрапити в опис PR.
8. Якщо задача не вкладається в день плану — асистент пропонує, що скоротити, за таблицею з `00-overview.md`, а не мовчки розтягує терміни.
