# 00 · Огляд і архітектура

## 1. Що будуємо

Хроніст — AI-компаньйон для дослідників українських архівів. Користувач відкриває скан на архівному порталі, виділяє фрагмент і за кілька секунд отримує транскрипцію рядок за рядком, сучасну орфографію, пояснення термінів і дат із джерелами. Підтверджені людиною транскрипції потрапляють у відкритий шар Commons, доступний через публічний пошук і MCP.

Повний контекст проєкту (концепт, факти, рішення, дизайн, статус) — у `docs/project-context.md`. Дизайн екранів — у Figma (файл `4UXNnyAAyCxTI5NqMtvQPM`) і дизайн-специфікації. Цей план описує, як дійти до демо 21 листопада 2026.

## 2. Межі MVP до 21 листопада 2026

Один наскрізний сценарій на одному типі документів, доведений до блиску. Команда підтвердила 1 листопада: до демо входить увесь must-список концепту.

**Входить (must), у порядку побудови:**
1. **Читання.** Розширення Chrome: бічна панель у переглядачі ARCHIUM (`archium.cdiak.archives.gov.ua`, рішення 14 листопада), виділення області скану, транскрипція рядок за рядком із підсвіткою рядків на скані й позначками непевних слів; читання робить мультимодальна модель через API за промптом `htr_vision`.
2. **Розуміння.** Нормалізація орфографії мовною моделлю; конвертація дат юліанський → григоріанський кодом; «Пояснити» термін, топонім або дату з посиланнями на довідковий корпус у 100–200 статей; без джерела — чесне «не знаю».
3. **Commons.** Редагування рядків, «Підтвердити» з підписом (вхід кодом із листа), збереження з шифром і координатами; при відкритті аркуша — підвантаження вже прочитаного; 50–200 аркушів демо-фонду оброблені заздалегідь.
4. **Діалог і цитата.** Чат «Спитати» з контекстом аркуша й посиланнями; експорт архівної цитати з шифром у трьох форматах.
5. **Публічний пошук.** Веб-сторінка пошуку за прізвищем або селом по Commons, без входу.
6. **MCP.** Сервер із трьома інструментами (`transcribe`, `explain`, `search_sources`) і 30-секундне демо в Claude Desktop.
7. **Веб-робоче місце (мінімум).** Завантажити власний скан → прочитати → підтвердити.

**Якщо лишиться час (should):** Rukopys-OCR-4B на Modal як основне читання (трек B у `04-ml-htr.md`); нотатник у розширенні; топоніми через Wikidata з картою; лічильник внеску; вивантаження CSV/JSON; archium.cdiak.

**Не входить:** ембединги й векторний пошук, масове скачування порталів, навчання власних моделей, мобільний застосунок, системний оверлей, Firefox, модерація й репутація, біллінг, темна тема.

**Порядок скорочення, якщо відстаємо** (рішення приймається на вечірньому синку в указаний день, фіксується в `docs/decisions.md`):

| Якщо на вечір… | …не готово | Ріжемо | Чим замінюємо на демо |
| --- | --- | --- | --- |
| 16 листопада | Commons у проді (редагування + підтвердження + підвантаження) | веб-робоче місце (пункт 7) | показуємо лише розширення; W5 пошук лишається |
| 17 листопада | чат «Спитати» без вигаданих джерел | чат (пункт 4, перша половина) | лише «Пояснити» з корпусу; у панелі вкладки «Спитати» немає |
| 18 листопада | MCP у Claude Desktop | MCP (пункт 6) | слайд «як це підключається» без живого демо |
| 18 листопада | публічний пошук | нічого не ріжемо | пошук — обов'язкова частина історії про Commons; переносимо сили з полірування |

Пункти 1–3 не ріжуться ні за яких умов: це і є продукт.

Демо-фонд: метричні книги XIX – початку XX ст.; конкретний фонд обирається до 4 листопада після інтерв'ю з істориком і тесту читабельності. У макетах використано демонстраційний шифр ЦДІАК, ф. 127, оп. 1012, спр. 3418.

## 3. Архітектура

```
                      ┌──────────────────────────────────────────────┐
  Клієнти             │  apps/extension (Chrome MV3, WXT, React)     │
                      │  apps/web (Vite React: пошук, робоче місце)  │
                      │  apps/mcp (MCP-сервер, тонкий адаптер)       │
                      └───────────────┬──────────────────────────────┘
                                      │ HTTPS + SSE, контракт packages/contracts
                      ┌───────────────▼──────────────────────────────┐
  Ядро                │  apps/api — Fastify 5, один процес           │
                      │  REST /v1/*, Better Auth, SSE статусу задач  │
                      │  фонові задачі в процесі (p-queue),          │
                      │  стан задач у таблиці recognitions           │
                      └──────┬──────────────────────────┬────────────┘
                             │                          │
             ┌───────────────▼───────────┐   ┌──────────▼───────────────────────────┐
  Дані й     │ PostgreSQL 18             │   │ Зовнішні API через LlmProvider        │
  сервіси    │ pg_trgm + tsvector        │   │ Anthropic Claude (основна, із зором)  │
             │ Commons, корпус, словник  │   │ Google Gemini (резерв, із зором)      │
             │ варіантів, користувачі    │   │ Resend (листи з кодом входу)          │
             └───────────────────────────┘   └──────────────────────────────────────┘
                                             ┌──────────────────────────────────────┐
                                  трек B →   │ services/htr на Modal (should)        │
                                             │ Rukopys-OCR-4B, POST /recognize       │
                                             └──────────────────────────────────────┘
```

Потік «прочитати фрагмент»: розширення вирізає область, рахує хеш → `POST /v1/recognitions` → API шукає в Commons за хешем і шифром → якщо нема, створює запис `recognitions(status=queued)` і ставить задачу у внутрішню чергу → задача викликає `htr.read(image)`: за замовчуванням мультимодальна модель за промптом `htr_vision` (structured output: рядки, слова, позначки непевності), при `HTR_URL` — HTR-сервіс треку B → `llm.normalize` → `llm.extractEntities` → `calendar.convert` → збереження → події в панель через SSE. Координати рядків: від HTR-сервісу — реальні, від мультимодальної моделі — рівні горизонтальні смуги в межах виділеної області з позначкою `boxSource: 'estimated'`; панель підсвічує смугу, а не точний контур. Ціль — до 8 с на фрагмент у 10–15 рядків.

## 6. Словник

- **Шифр** — адреса документа в архіві: архів / фонд / опис / справа / аркуш. У даних — `archive`, `fond`, `opys`, `sprava`, `folio`.
- **Аркуш (page)** — одна сторінка скану; `folio` може мати зворот: `14зв`.
- **Регіон (region)** — прямокутник на аркуші, який читав користувач; координати в частках від розміру зображення (0…1), не в пікселях.
- **Транскрипція (transcription)** — результат читання регіону: сирі рядки, рядки після правок, нормалізований текст, статус `draft` / `verified` / `disputed`, версія.
- **HTR** — handwritten text recognition, розпізнавання рукопису. У цьому плані «HTR» означає будь-який спосіб читання: мультимодальну модель (трек A) або спеціалізовану модель (трек B).
- **CER / WER** — частка помилок на символ / на слово між розпізнаним і еталонним текстом.
- **Золотий набір (gold set)** — 30+ рядків, вручну транскрибованих істориком, для вимірювання CER.
- **Корпус (knowledge base)** — довідкові статті з джерелами й ліцензіями, порізані на чанки; з нього беруться пояснення.
- **Словник варіантів (synonyms)** — таблиця «термін → варіанти написання», якою розширюється пошуковий запит.
- **Commons** — публічний шар підтверджених транскрипцій і сутностей, ліцензія CC BY 4.0.
- **MCP** — Model Context Protocol, стандарт підключення інструментів до AI-клієнтів.
