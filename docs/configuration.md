# Конфігурація Хроніста

Перелік змінних середовища, режимів і числових обмежень, які читає код. Значення за замовчуванням узято з коду, а не з `.env.example`. Секретів і справжніх значень тут немає: лише назви й безпечні приклади. Загальну будову системи описано в [architecture.md](architecture.md).

## 1. Звідки береться конфігурація

- **API** (`apps/api/src/config.ts`): змінні розбираються один раз під час запуску схемою Zod (`loadConfig`). Некоректна конфігурація зупиняє процес із повідомленням `Invalid configuration: …`. Порожній рядок вважається незаданою змінною (`emptyToUndefined`).
- **Файл `.env`.** У корені репозиторію лежить `.env.example`; робочий `.env` у git не потрапляє (`.gitignore`). Скрипти `dev`, `db:migrate`, `read-fragments`, `api-key:create`, `readings:import` запускаються з `--env-file-if-exists=../../.env`; Node не перезаписує змінні, уже задані в оболонці. Скрипт `start` (`node src/server.ts`) `.env` не читає: на хостингу значення беруться із середовища.
- **Розширення й веб** змінних середовища не читають: адреса API залежить від режиму збірки (розділ 7).
- **MCP-сервер** читає `KHRONIST_API_URL` і `KHRONIST_API_KEY` (розділ 6).
- **Python (`services/knowledge`)** читає `KHRONIST_API_URL`, `KHRONIST_API_KEY`, `ADMIN_API_KEY` (розділ 6).

Колонка «Обов'язкова в проді» означає: чи вимагає цього код або чи без значення відповідна функція недоступна. Де значення потрібне лише за певної умови, умову описано.

### 2.7. Перевірки конфігурації в `production`

`loadConfig` у `NODE_ENV=production` відмовляє у запуску, якщо:

- `LLM_FIXTURES` увімкнено;
- немає ключа для `HTR_MODEL_PRIMARY` або для `LLM_MODEL_PRIMARY` (тип ключа визначається префіксом імені: `gemini-` → `GOOGLE_API_KEY`, інакше `ANTHROPIC_API_KEY`);
- не задано `RESEND_API_KEY`;
- `BETTER_AUTH_URL` не починається з `https://`;
- `ADMIN_API_KEY` задано, але він коротший за 32 символи.

У будь-якому середовищі запуск зупиняється, якщо: задано `HTR_MODEL_FALLBACK` чи `LLM_MODEL_FALLBACK` без відповідного ключа; задано `RESEND_API_KEY`, але не всі з `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `MAIL_FROM`; задано `HTR_URL`; ім'я моделі не починається з `claude-` чи `gemini-`.

Стан сервісу `GET /health` (`routes/health.ts`) відбиває конфігурацію: `llm` — `ok`, якщо є ключ основної моделі тексту, інакше `degraded` (резервну модель і `HTR_*` ця перевірка не враховує); `htr` — `fixture`, `vision` або `down` (немає читача).

## 3. Режим `LLM_FIXTURES`

Призначений для розробки, тестів і CI (`.env.example` ставить `LLM_FIXTURES=1`; задача `runtime` у `.github/workflows/ci.yml` теж). Моделі не викликаються, бюджет `model_calls` не витрачається, ключі не потрібні. У `production` режим заборонено.

| Частина системи                       | Поведінка при `LLM_FIXTURES=1`                                                                                                                                       |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Читання (`services/htr/fixture.ts`)   | Будь-яке зображення дає той самий демонстраційний текст із трьох рядків; `reader = 'fixture'`; `/health` показує `htr: "fixture"`                                    |
| Нормалізація                          | Пропускається (`passthroughNormalizer`): нормалізований текст дорівнює прочитаному, розкриттів скорочень немає                                                       |
| Сутності й переклад                   | Не виконуються (порожній список сутностей, перекладу немає)                                                                                                          |
| «Пояснити»                            | Пошук по корпусу працює; якщо джерела не знайдено — `answer: null`, `reason: "no_sources"`. Якщо знайдено, а моделі немає: для дат повертається лише перерахунок дати кодом, для решти — `503 reader_unavailable` |
| Чат                                   | Без запису й без впевнених чанків — `no_sources`; інакше `503 reader_unavailable`                                                                                    |
| Кеш                                   | Фікстурні транскрипції потрапляють у БД і далі віддаються з кешу як справжні; перед переходом на справжні моделі базу варто очистити (локально — `docker compose -f infra/docker-compose.yml down -v`, `up -d`, `pnpm db:migrate`) |

Для оцінки «Пояснити» й чату (`services/knowledge/eval/run_qa.py`) потрібен `LLM_FIXTURES=0` (див. `services/knowledge/README.md`).

## 4. Налаштування моделей

Задачі мають два набори змінних:

- `HTR_*` — лише читання фрагмента (`htr_vision`);
- `LLM_*` — нормалізація, сутності, переклад, «Пояснити» й чат.

Постачальник обирається за префіксом імені моделі (`config.ts`, `hasKeyFor`; `services/llm/select.ts`): `claude-*` — Anthropic (`services/llm/anthropic.ts`), `gemini-*` — Google (`services/llm/gemini.ts`).

Поточні значення на проді (`.railway/railway.ts`): `HTR_MODEL_PRIMARY=claude-sonnet-5-5`, `HTR_MODEL_FALLBACK=gemini-3.6-flash`, `LLM_MODEL_PRIMARY=claude-sonnet-5-5`, `LLM_MODEL_FALLBACK` не задано. `HTR_EFFORT` і `LLM_EFFORT` на Railway не задані, тож діє `medium`.

Параметри запитів до провайдерів, зашиті в коді:

| Параметр                          | Anthropic (`anthropic.ts`)                                                                                           | Gemini (`gemini.ts`)                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Структурований вихід              | `output_config.format` типу `json_schema` зі схемою Zod                                                              | `response_format` із `application/json` і схемою Zod             |
| Глибина роздумів                  | `output_config.effort` = `HTR_EFFORT` або `LLM_EFFORT`                                                               | `thinking_level` = `low` завжди                                  |
| Повтори SDK                       | `maxRetries: 0`                                                                                                      | `retries.strategy: 'none'`, `store: false`                       |
| Серверний запасний варіант        | бета-заголовок `server-side-fallback-2026-07-01`, `fallbacks: 'default'`                                             | немає                                                            |
| Додаток до системного промпту     | немає                                                                                                                | `<промпт>/gemini.md` для `htr_vision`, `explain`, `chat`         |

Задачі: токени виходу, обмеження часу й джерело налаштувань:

| Задача (промпт) | Набір змінних | Макс. токенів виходу | Ліміт основної моделі, якщо є резерв | Загальний тайм-аут | Частка бюджету, до якої задача працює |
| --------------- | ------------- | -------------------- | ------------------------------------ | ------------------ | ------------------------------------- |
| Читання (`htr_vision`) | `HTR_*` | 4096 | 15 с | 75 с | 100 % |
| Нормалізація (`normalize`) | `LLM_*` | 8192 | 20 с | 30 с | 100 % |
| Сутності (`entities`) | `LLM_*` | 4096 | 8 с | 20 с | 100 % |
| Переклад (`translate`) | `LLM_*` | 8192 | 15 с | 25 с | 100 % |
| «Пояснити» (`explain`) | `LLM_*` | 2048 | 15 с | 30 с | 75 % |
| Чат (`chat`) | `LLM_*` | 2048 | 15 с | 30 с | 75 % |
| Перенормалізація після правки | `LLM_*` | як нормалізація, сутності й переклад | як вище | як вище | 75 % |

Значення з `apps/api/src/lib/limits.ts` і `services/*`; змінюються лише правкою коду.

Правила вибору й перемикання моделей:

- Якщо основна модель без ключа, а резервна з ключем, резервна стає основною; тож запуск лише з ключем резервної моделі можливий.
- На резерв переходять, коли основна збоїть або не вклалася в ліміт часу; помилки ліміту й білінгу провайдера (HTTP 402, 429) на резерв не перемикають.
- Невалідний вихід (не JSON або не за схемою) повторюється один раз тією самою моделлю.
- Кожен виклик моделі, включно з повтором і резервом, витрачає одну одиницю добового бюджету.

## 7. Розширення й веб

Змінних середовища немає. Адреса API залежить від режиму збірки (`import.meta.env.MODE`):

| Режим                                                                      | Адреса API                  | Де задано                                                                    |
| -------------------------------------------------------------------------- | --------------------------- | ---------------------------------------------------------------------------- |
| `development` (`wxt dev`; `vite` dev-сервер; `vite build --mode development`) | `http://localhost:3000`  | `apps/extension/api/origin.ts`, `apps/web/src/api/origin.ts`                 |
| будь-який інший (`wxt build`, `vite build`)                                | `https://api.khronist.org`  | ті самі файли                                                                |

У розширенні та сама адреса потрапляє в `host_permissions` манифесту (`apps/extension/wxt.config.ts`). Порти розробки: `wxt dev` — 3001 (`strictPort`), веб `vite` і `vite preview` — 5173 (`strictPort`); локальний `CORS_ORIGINS` у `.env.example` дозволяє саме `http://localhost:5173`.

Сховище розширення (`browser.storage`): `sessionToken` (`storage.session`), `firstRunSeen` і `confirmWithoutAsking` (`storage.local`).

## 9. Приклад `.env` для розробки

Безпечні значення для локального запуску з фікстурами (без викликів моделей):

```sh
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://khronist:khronist@localhost:5432/khronist
CORS_ORIGINS=http://localhost:5173
LLM_FIXTURES=1
```

Для локального входу за кодом додатково потрібні `RESEND_API_KEY`, `MAIL_FROM`, `BETTER_AUTH_SECRET` (не менше 32 символів) і `BETTER_AUTH_URL=http://localhost:3000`, а для підтвердження транскрипцій — `VERIFIER_EMAILS` із вашою поштою. Для справжнього читання задайте `ANTHROPIC_API_KEY` і приберіть `LLM_FIXTURES`.
