# Як працювати з репозиторієм

Запуск проєкту описаний у [README.md](README.md).

## Шлях однієї зміни

```sh
git switch main
git pull
pnpm install
git switch -c feat/short-name
```

1. Одна задача — одна гілка. Назва англійською: `feat/...`, `fix/...`, `chore/...`, `docs/...`.
2. Коміти невеликі, повідомлення англійською: `feat: add recognition endpoint`.
3. Запуште гілку й відкрийте PR у `main`. Шаблон PR підставиться сам.
4. Дочекайтесь зеленого CI й злийте PR.

`pnpm install` після кожного `git pull` обов'язковий: без нього нові залежності з `main` не встановляться, і код упаде на імпорті.

## Автоматичні перевірки

| Коли          | Що запускається                            | Де                               |
| ------------- | ------------------------------------------ | -------------------------------- |
| перед комітом | `pnpm lint`, `pnpm typecheck`, `pnpm test` | локально, `.githooks/pre-commit` |
| перед пушем   | заборона прямого пушу в `main`             | локально, `.githooks/pre-push`   |
| на кожному PR | `pnpm lint`, `pnpm typecheck`, `pnpm test` | GitHub Actions, задача `check`   |

Хуки вмикає `pnpm install`. Перевірка: `git config core.hooksPath` має вивести `.githooks`.

Прапорець `--no-verify` обходить хуки, але не CI. Не використовуйте його, щоб приховати падіння тестів.

Поки репозиторій приватний, GitHub може не блокувати злиття PR із червоним CI, тому не зливайте такі PR. Хуки поки не перевіряють `services/*`: там перед комітом запускайте `uv run ruff check && uv run pytest`.

## Правила коду

- Код, імена й коміти англійською; інтерфейс, промпти для користувача й документація українською.
- Коментарів у коді немає. Пояснення виносьте в назви, типи й README теки.
- TypeScript strict без `any`, Zod на межах. Python 3.12 з типами, ruff, Pydantic на межах.
- Контракти в `docs/plan/07-contracts.md` — джерело правди. Зміна контракту — окремий PR, який погоджують обидві сторони.
- Нічого не вигадуємо: ні фактів про архіви, ні джерел, ні назв моделей чи версій пакетів. Невідоме перевіряємо або позначаємо `TODO(перевірити)`.
- В інтерфейсі лише чесні стани: немає функції — немає кнопки, невпевненість моделі видно.
- Секрети лише через env. Нова змінна одразу додається в `.env.example`. Файл `.env` у git не потрапляє.
- Рішення й скорочення обсягу записуємо в `docs/decisions.md` того ж дня.
- Зміни в чужій зоні (власники вказані в [README.md](README.md)) описуємо в PR, а не робимо мовчки.

Повний перелік правил — у [CLAUDE.md](CLAUDE.md).

## Типові проблеми

| Симптом                                                   | Причина                                              | Що зробити                                                                    |
| --------------------------------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------- |
| `Cannot find package` після `git pull`                    | не встановлені нові залежності                       | `pnpm install`                                                                |
| `failed to connect to the docker API`                     | Docker Desktop не запущений                          | запустити його й повторити команду                                            |
| порт 5432 зайнятий, контейнер не стартує                  | працює інший PostgreSQL                              | зупинити його                                                                 |
| `/health` повертає 503 і `db: "down"`                     | база не запущена або неправильний `DATABASE_URL`     | `docker compose -f infra/docker-compose.yml up -d`, перевірити `.env`         |
| помилка про відсутню таблицю                              | не застосовані міграції                              | `pnpm db:migrate`                                                             |
| помилка про `pg_trgm` на наявній базі                     | `infra/init.sql` виконується лише на порожньому томі | `docker compose -f infra/docker-compose.yml down -v`, це стирає локальні дані |
| нові фрагменти дають 503, `htr: "down"`                   | немає ні `LLM_FIXTURES=1`, ні `ANTHROPIC_API_KEY`    | задати одне з двох у `.env`                                                   |
| коміт проходить без перевірок                             | хуки не ввімкнені                                    | `pnpm install`, перевірити `git config core.hooksPath`                        |
| `uv` або `gh` не знайдено одразу після встановлення       | термінал не бачить новий `PATH`                      | перезапустити термінал і редактор                                             |
| `gh` пише `The token in GITHUB_TOKEN is invalid`          | у системі задано застарілий токен                    | видалити змінну `GITHUB_TOKEN`, виконати `gh auth login`                      |
| на хостингу `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` | використано `pnpm deploy` або копію `node_modules`   | ставити все монорепо, запускати `pnpm --filter @khronist/api start`           |
